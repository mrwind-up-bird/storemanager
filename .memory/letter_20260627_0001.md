## 3. The "Pain" Log (CRITICAL)
* **The #1 architectural trap (all 4 lenses agree):** v1 got tenant isolation "for free" via a monkey-patched `pg.Pool.connect()` interceptor + AsyncLocalStorage. **Next.js + Drizzle does NOT have this.** → v2 MUST make `withTenant(ctx, fn)` (a `BEGIN; SET LOCAL app.current_tenant/current_user_id/is_superadmin; …; COMMIT` transaction) the **single, enforced** DB surface; raw Drizzle client banned via `server-only` + ESLint. **Never use connection-scoped `SET`** (leaks across pooled connections = silent cross-tenant breach). *Do not retry the "isolation is automatic" assumption.*
* **drizzle-kit does NOT manage RLS** (policies, FORCE RLS, non-superuser role, GRANTs, GUC defaults). Keep these as explicit ordered SQL migration steps; use `drizzle-kit generate`, **never `push`** in shared/prod. Add a boot-time assertion (app role ≠ superuser; every tenant table has rowsecurity+force+policy).
* **Auth.js v5 sessions are NOT tenant-bound** by default → confused-deputy across subdomains. Must assert `session.user.tenantId === resolvedTenantId` (403 otherwise); composite `UNIQUE(email, tenant_id)`; custom Drizzle adapter; `__Host-` host-only cookies (= login per tenant).
* **pg-boss** must run as its **own worker process/service** (not inside `next start`); every job payload carries `tenant_id`; pgboss schema excluded from tenant RLS.
* **GUC name gotcha:** use `app.current_user_id`, NOT `app.current_user` (reserved). **No default-tenant fallback** anywhere (v1's `DEFAULT 1` = silent mis-assignment).
* **<5-min deploy** threatened by: build-on-server, Google-CDN fonts, migrate-on-boot with `CREATE INDEX CONCURRENTLY` inside a tx. → CI-prebuilt `output:'standalone'` image, self-host fonts via `next/font/local`, gated migrations, CONCURRENTLY outside tx.
